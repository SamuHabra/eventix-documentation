## 1. Objectif de la phase

Cette phase définit le cadre organisationnel, méthodologique et documentaire dans lequel nous allons  concevoir la plateforme Eventix.

Elle ne définit pas encore les fonctionnalités détaillées d'Eventix, son architecture technique ou ses choix technologiques.

L'objectif est de disposer d'un cadre commun nous permettant  de travailler de manière structurée, traçable et cohérente pendant toutes les phases suivantes.

## 3. Méthode de collaboration

Le dépôt GitHub constitue la source de vérité documentaire du projet.

Les membres travaillent sur des branches individuelles puis soumettent leurs modifications par Pull Request.

Le workflow général est :

```text
Sujet
  ↓
Discussion
  ↓
Analyse
  ↓
Documentation
  ↓
Review
  ↓
Vote si nécessaire
  ↓
Validation
  ↓
Merge
```

## 4. Format documentaire

Le format officiel de la documentation Eventix est **Markdown (`.md`)**.

GitHub est utilisé pour :

* versionner la documentation ;
* suivre les modifications ;
* conserver l'historique ;
* effectuer les reviews ;
* tracer les décisions.

Les documents Google Docs peuvent être utilisés comme espace de travail collaboratif, mais la documentation validée doit être intégrée au dépôt GitHub.

## 6. Principes de travail

L'équipe Eventix adopte les principes suivants :

1. Comprendre le métier avant de concevoir la technologie.
2. Ne pas prendre de décision technique prématurée.
3. Documenter les décisions importantes.
4. Identifier explicitement les hypothèses.
5. Conserver les questions non résolues.
6. Challenger les propositions plutôt que les accepter automatiquement.
7. Préserver la traçabilité des décisions.
8. Valider chaque phase avant de passer à la suivante.
9. Concevoir Eventix en fonction du marché camerounais.
10. Rechercher les compromis entre valeur métier, coût, performance, sécurité, résilience et scalabilité.
